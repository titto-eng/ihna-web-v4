# 05 · Design system

## 1. Purpose
The visual layer of the site: Tailwind v4 tokens (`src/styles/theme.css`), fonts, layout components (`src/components/layout/`), the audience switch (`src/components/audience/`), the course key-facts strip (`src/components/course/`) and the page templates (`src/components/templates/`, `src/components/templates/landing/`). The layout system is the BON prototype's (Fraunces display, mono labels, pill buttons, card radius) in IHNA's palette: teal primary, the old theme's dark teal for text and ink, orange secondary. Block configs and renderers: `20-blocks.md`; landing templates in detail: `60-landing.md`.

## 2. Data model
Owns no collections. Reads:
- code constants: `src/content/nav.ts` (utility links, menu with groups, primary/secondary CTA, promo bar), `src/content/footer.ts` (columns, newsletter, Acknowledgement of Country and its `acknowledgementLink`, legal lines/links, social), `src/content/site.ts` (site name, short name, `titleTemplate`, logo, phones, email, `organisation`, `contact`, `social`, WhatsApp number, `allowedEmbedHosts`, `defaultFormKey`), `src/content/pages.ts` (each route file's `template` label and the `sections` of `SectionNav`), `src/content/campuses.ts` (`campusContacts`, empty on IHNA; `galleryCampuses`, the four city campuses with their App Runner ids and page paths, also the home page's campus list), `src/content/news.ts` (the `/news/` listing), `src/content/course-siblings.ts` (domestic/international course pairs), `src/content/library/catalogue.ts` (the library reading list by unit);
- `sectionFields` (`src/blocks/sectionFields.ts`) on every block: `tone` (default | card | muted | ink | sunrise), `spacing` (default | compact | none), `anchorId`;
- `courses` (incl. `facts` / `factsInternational`, `sections`, `showStartDates`, `studentType`), the `courseShared` global, `lookups` (campuses, categories, …), `staff`, `posts`, `galleries`, `testimonials` for the data-driven templates.

## 3. Admin capabilities
Marketing sets tone, spacing and anchor per block in course section layouts and `courseShared`, and edits each course's key facts (`courses.facts`, `courses.factsInternational`, DEC-67). Tokens, fonts, header, footer, templates and route-file pages are code: a developer edits the file and deploys (DEC-61, DEC-63).

## 4. Front-end behaviour

### 4.1 Tokens: `src/styles/theme.css`
The only site stylesheet (imported by `src/app/(site)/layout.tsx`): `@import 'tailwindcss'`, `@plugin '@tailwindcss/typography'`, `@import 'tw-animate-css'`, then one `@theme` block of literal values. `src/app/(payload)/custom.scss` is the admin's stylesheet hook and is empty.

| Token | Value | Token | Value |
|---|---|---|---|
| background | hsl(180 25% 97%) | foreground, ink | hsl(190 60% 11%) |
| card, popover | hsl(180 30% 99%) | muted | hsl(178 22% 91%) |
| muted-foreground | hsl(190 25% 36%) | border | hsl(180 18% 84%) |
| input | hsl(180 18% 80%) | ring | hsl(178 100% 30%) |
| primary (teal, near the old `#009791`) | hsl(178 100% 31%) | primary-strong (dark teal, `#003f4a`) | hsl(189 100% 15%) |
| secondary (orange, `#f7941d`) | hsl(33 93% 54%) | accent | hsl(189 100% 15%) |
| destructive | hsl(0 72% 45%) | ink-raised | hsl(190 55% 15%) |
| primary-, accent-, ink-, destructive-foreground | hsl(180 30% 99%) | secondary-foreground | hsl(190 60% 11%) |
| chart-1…5 | primary, secondary, primary-strong, ink, hsl(180 18% 60%) | | |

Contrast (WCAG ratios of these values): `primary` on `background` is 3.1:1 and fails AA for text, so text, links and emphasis on light surfaces use `primary-strong` (10.7:1 on background, 9.5:1 on muted; DEC-16). Everything filled with `primary` (buttons, active tabs and pills, the video play disc) carries `foreground` text (4.7:1); buttons switch to `primary-strong` with light text on hover (11.1:1), and focus adds a `ring` outline without changing the text pair. `ring` stays at hsl(178 100% 30%) (3.3:1 against `background`, above the 3:1 for focus indicators). `tests/templates/contrast.test.ts` checks these pairs from `theme.css`. `secondary` is used for text only on `ink` (6.9:1); on `background` it is 2.1:1 and stays decorative (underlines, quote borders). `muted-foreground` is 5.5:1 on background, 4.9:1 on muted.

- **Fonts** (`next/font/google` in `src/app/(site)/layout.tsx`, self-hosted at build, `display: 'swap'`): Fraunces (`opsz` + `SOFT` axes, normal and italic) → `--font-fraunces`; Bricolage Grotesque → `--font-bricolage`; Spline Sans Mono 400/500 → `--font-spline-mono`. The theme maps them to `--font-display` (→ Georgia, serif), `--font-sans` (→ system-ui) and `--font-mono` (→ ui-monospace). Body is `font-sans`; h1–h4 are `font-display` with `text-wrap: balance`.
- **Utilities**: `display` (Fraunces, weight 300, tracking −0.02em, optical sizing auto); `label-mono` (mono, 0.75rem, uppercase, tracking 0.2em); `bg-sunrise-glow` (orange and dark-teal radial gradients over a teal → dark-teal linear gradient, behind the split hero image); `reveal` (view-timeline fade-in, only inside `@supports (animation-timeline: view())`, so content is never hidden where unsupported).
- **Type scale**: `text-display-xl` clamp(3rem, 8.4vw, 7.4rem)/0.92 (hero h1); `text-display-lg` clamp(2.6rem, 7vw, 6rem)/0.95; `text-display-md` clamp(2.2rem, 5vw, 4.2rem)/0.98 (section h2, compact hero h1); `text-display-stat` clamp(3rem, 8vw, 6rem)/1.
- **Containers**: `max-w-site` 1320px; `max-w-prose-site` 72ch; `Container narrow` = `max-w-4xl`.
- **Radius**: sm 0.375rem, md 0.75rem, lg 1rem, xl 1.5rem, `rounded-card` 1.75rem; buttons and pills `rounded-full`.
- **Motion**: `animate-rise` (0.7s, 14px rise; hero h1 and subheading); `reveal` (1s, 40px). Hover lifts are `-translate-y-0.5`. Under `prefers-reduced-motion: reduce` the base layer disables every animation, transition and smooth scroll.
- **Base layer**: borders default to `border`; `:focus-visible` is a 2px `ring` outline; `.prose` maps `--tw-prose-*` to tokens (links and counters `primary-strong`, bullets `primary`, quote border `secondary`).
- **Emphasis**: headings mark one phrase with `*asterisks*`; `src/components/Emphasis.tsx` renders it as an italic `<em>` in `primary-strong` (`secondary` on dark).
- **Buttons**: `src/components/ui/button.tsx` (shadcn); `src/components/CtaLink.tsx` maps CTA styles `primary` → default, `secondary` → outline, `link`, `ink`, `light`.
- Breakpoints are Tailwind defaults; the header adds one arbitrary step at 1440px (`min-[1440px]:`, §4.2).

### 4.3 Audience switch (`src/components/audience/`)
- `AudienceProvider` (client, in the site layout): state `domestic` | `international` (default `domestic`), exposed as `data-audience` on a `group/aud` wrapper.
- `AudienceSwitch` (client): BON segmented pill, `role="radiogroup"` with two `role="radio"` buttons and `aria-checked`. Rendered by the hero when `audienceSwitch` is true (CourseDetail sets it for `studentType: 'both'` courses: 2 of the 21).
- `AudienceOnly` (server): wraps one audience's version; the inactive one is hidden by `group-data-[audience=…]/aud:hidden`. Audience-aware output (`admissionsPanel`, `startDates`, `CourseFacts`) puts both versions in the server HTML, so the page works without JS.

### 4.4 Course key facts (`src/components/course/`)
- `facts.ts` (pure: no React, no Payload): `FACT_KEYS` = duration, units, delivery, level, campuses, cricos, fee, with `FACT_LABELS`. `courseFactsFor(course, audience)` resolves each fact from `courses.facts.<key>` ({show, value, detail}); for the international audience of a `both` course, `factsInternational.<key>` wins when it has a value or `show: false`. A blank value falls back to the course's own fields (lookup names of `durations`, `deliveryModes`, `levels`, `campuses` joined with " · "; `units` → "N units"; `cricosCode`; `fees.displayAmount` with `fees.note` as detail). `show: false`, or no value after the fallback, drops the fact. `factListsFor`, `hasCourseFacts` and `audiencesOf` build on it.
- `CourseFacts.tsx` (server): `<CourseFacts course audience? only? className? variant? />` renders a `<dl>`: `variant` `strip` (default) is the BON strip; `tiles` is a row of cards, each with a lucide icon on a brand-blend gradient tile (`mint`, `ocean`, `sun`, `coral` tokens), mono label, value and detail, fading in one after another (CourseDetail). The strip (2 → 3 md → 4 lg columns; `label-mono` term, `display` value, muted detail). Without `audience`, a `both` course renders one strip per audience inside `AudienceOnly`, or a single strip when both audiences resolve to the same facts. It renders nothing when no fact resolves. It needs the course doc at depth ≥ 1 (lookup names). A route file can drop `<CourseFacts course={course} />` into any hand-written course page; `CourseLanding` uses it on the landing pages.
- `CourseDetail` places the `tiles` variant over the bottom edge of its hero unless a `courseFacts` block appears anywhere in the course's section layouts. The `courseFacts` block (`20-blocks.md`) is a thin wrapper around the same component.
- `scripts/dev/fill-course-facts.ts [--dry] [--offline]` fills blank `facts.<key>.value/detail` from the course's fields and the live course page (never overwrites a value; sets `facts.cricos.show = false` on domestic-only courses); report in `scripts/dev/out/course-facts-report.json`.

### 4.6 Carousels
- **Primitive**: `src/components/ui/carousel.tsx` (shadcn, embla). `Carousel` is a `role="region"` with `aria-roledescription="carousel"`; `CarouselItem` is a `role="group"` slide. ArrowLeft / ArrowRight move it, drag and swipe come from embla, and embla scrolls a slide into view when focus enters it. Under `prefers-reduced-motion: reduce` (`useReducedMotion`) the buttons, dots and keys jump instead of animating. The context (`useCarousel`) exposes `selectedIndex`, `snapCount`, `scrollTo` and `reducedMotion`; `CarouselDots` (one button per snap point, `aria-current` on the selected one, the selected dot a wider `primary-strong` pill, `secondary` on ink) and `CarouselCounter` (`label-mono` "02 / 12") read them.
- **`SlideCarousel`** (`src/components/blocks/SlideCarousel.tsx`, client): the site carousel (DEC-71). Props: `label` (region name), `perView` 1 / 2 / 3 / 4 (1 = always one; 3 = 1 → 2 md → 3 lg; 4 = 1 → 2 md → 4 lg), `indicator` (`dots`, or `counter`; default dots up to 8 slides, counter above), `autoplay` (ms; off by default), `loop`, `onDark`, `className`, `slideClassName`. Server components pass the slides as children, so every slide is in the server HTML. Each slide is labelled "n of N"; an `sr-only` polite live region announces "Slide n of N" after a move. Controls sit under the slides: round outline prev / next buttons (40px), then the indicator; when every slide is already in view the row turns invisible and keeps its height. Autoplay never runs under reduced motion, stops while the pointer is over the carousel or focus is inside it and while the tab is hidden, shows a Pause / Play button at the end of the controls row, and silences the live region while it runs.
- **`CardCarousel`** (`src/components/blocks/CardCarousel.tsx`): `SlideCarousel` with `perView` 3 (or 2 / 4) and no autoplay, for card rows: featured courses, `relatedCourses`, `cardGrid` carousel variant, `testimonials`.
- **Hero carousel** (`src/blocks/hero/HeroCarousel.tsx`, server): several hero slides in one `Section`, one per view, looping, autoplay every 8 s (`HERO_AUTOPLAY_MS`) with the rules above. Each slide is `HeroContent` (the split / compact hero without its section; a `full` slide renders as split). Slide one holds the page h1, the `animate-rise` text and the preloaded image; later slides use h2 and lazy images. A single slide renders the plain `hero` block. `HomeView` uses it when the page passes an array as `hero`; the home route file holds the slides as code (DEC-61).
