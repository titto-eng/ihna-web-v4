# 30 — Import (`scripts/import/`)

## 1. Purpose
Loads IHNA content from the old WordPress site, its App Runner content API and the old repo into Payload as blocks only (AGENTS.md rule 5): `courses`, `posts` (the blog), `blogCategories`, `galleries`, `staff`, the four course lookups, `media`, `documents`, plus the static file stores in `public/`. Pages, landing pages, menus, forms, news items and redirects are code (`src/app/(site)/**`, `src/content/*`, DEC-61/62/63) and have no import step.
Every step is a file in `scripts/import/steps/`, is idempotent, and writes `scripts/import/out/ihna-<step>.report.json`. Reports carry counts, ids, paths and reasons, never body text.

## 2. Data model
- `posts`, `courses`: `import` group (`importGroup()`, `src/collections/shared/fields.ts`): `wpId` (unique; the upsert key of courses), `importClass` (`A | B | C-lite | C | D | new`, from `html-analysis.csv:class`), `reviewStatus` (`auto | check | needs-rebuild | kh-unresolved | ok`, DEC-23), `importReport` (json: hashes, reasons, coverage), `reviewedBy`, `reviewedAt`. Only a signed-in person can set `ok`; the `stampReview` hook (`src/collections/shared/hooks.ts`) stamps `reviewedBy`/`reviewedAt` and reverts `ok` written by a script.
- `posts.import.apprunnerId` (unique, the upsert key of blog posts) and `import.sourceUpdatedAt`; `posts.urlDate` + `slug` (DEC-104), `cardImage`, `topic` (→ `blogCategories`).
- `blogCategories.legacyCode` (unique: the App Runner category code); `galleries.apprunnerId` (unique), `galleries.items[].apprunnerId`, `galleries.sourceUpdatedAt` (hidden hash of the source).
- `courses.khId` + `khIdSource` (`scrape`), `showStartDates`, `fees` (fee text, DEC-107), `brochureUrl`, `handbookUrl`, `hubspotCourseId`; the import leaves the `courseShared` global (DEC-22) alone: `layout` stays empty on IHNA, `stats` comes from `scripts/dev/seed-live-figures.ts`.
- `staff.legacyId` (unique: the `staff_profile` id of `/staff-profile/?id=<id>`, DEC-111), `staff.sortOrder` (directory order), `staff.courses` (courses the person manages; read by the CourseManagers block, DEC-60).
- `media.legacyPath` (unique): original path without host or leading slash: `wp-content/uploads/...`, `wp-content/themes/mwt-ihna/assets/...` or, for App Runner images, `static/images/{desktop,mobile}/{blog,gallery}/<id>.webp`.
- Lookups (`src/collections/Lookups.ts`): keyed by `slug`. `categories` (schools), `levels`, `disciplines` (areas of interest) and `universities` come from `seeds/ihna-course-groups.json`; `levels`/`disciplines.legacyId` = the id in the live course finder (`course-urls.json`). `campuses`, `deliveryModes`, `durations` are ensured per course from the page facts.
- `documents.publicPath` (unique): the public URL of the PDF (DEC-68).

## 3. Admin capabilities
Imports are CLI-only. Marketing works the review queue by filtering `import.reviewStatus` (a default column on courses; a filter on posts) and reading `import.importReport.reasons`, then sets `ok`. A doc set to `ok` keeps `ok` on re-import while its source is unchanged and is skipped by `import:refresh`. Marketing owns blog-category labels and gallery title, order, visibility and `featured` once imported.

## 4. Front-end behaviour
Imported docs render like any other. Writes pass `context: { importing: true }` and `overrideAccess: true`; collection hooks skip revalidation and the URL-change guard when `importing` is set (DEC-23, DEC-64). After every non-dry step `cli.ts` POSTs `{ all: true }` to `${NEXT_PUBLIC_SITE_URL}/api/revalidate/` with header `x-revalidate-secret: REVALIDATE_SECRET` (DEC-33); `documents` also posts `{ tags: ['documents', 'collection:documents'] }`. Without `REVALIDATE_SECRET`, or with the dev server down, the cache is not cleared and a warning is printed.

## 5. URLs
- Posts (DEC-104): the App Runner slug is the whole path after `/blog/`: `2024/06/<slug>` → `urlDate` `2024/06` + `slug`, path `/blog/2024/06/<slug>/` (172 posts); a flat slug → `/blog/<slug>/` (14). The month is never derived from `published_date` (6 dated slugs differ from it). The upsert fails an item whose stored `path` differs from its live path.
- Courses: the `pages.csv:path` of the course (`/courses/<slug>/`). The international pages are courses of their own at their own URLs (`-int`, `-international`, `-international-students`); the pairs are `src/content/course-siblings.ts` (the course route's student-type switch).
- Staff: `/staff-profile/?id=<legacyId>` (DEC-111); `/academic-staff/` lists them.
- Galleries: `/all-events/` (`?campus=<App Runner campus id or key>`) and the campus pages (DEC-105).
- Documents: served at `publicPath` under the `DOCUMENT_PREFIXES` of `src/content/documents.ts` (`/pdf/`, `/ihna-policies/`, `/ihna-procedures/`, `/IHNA_International_Course_Guide/`, `/alumni/docs/`, `/wp-content/uploads/pdf/`, `/wp-content/uploads/guides/`, `/brochures/`) through the proxy rewrite to `src/app/(site)/pdf/[...path]/route.ts` (DEC-68).
- Links in imported content: links to the page's own host (`ihna.edu.au`, with `www.` and `uat.`) become site-relative; internal links that are neither in `pages.csv` nor a post URL are reported as `dead-link` (`lib/links.ts`), `uat.*` links are reported, file links (PDF, uploads) are kept.

## 6. Integrations
- Inputs (paths fixed in `lib/config.ts` and the steps; no env override): `../inventory/data/ihna/{pages,posts,courses}.json` (144/4/21 WP REST items), the App Runner snapshots `../inventory/data/ihna/apprunner/*.json`, `../inventory/v2/ihna/{pages,html-analysis,landing-pages}.csv`, the old repo `../ihna-web-2.0/` (`LEGACY_ROOT`; theme `wp-content/themes/mwt-ihna/` = `LEGACY_THEME`, static stores, the listed upload PDFs) and `scripts/import/seeds/` (site-specific: `ihna-course-groups.json`, `documents.ts`, `static-held.json`).
- Env: `DATABASE_URL`, `PAYLOAD_SECRET` (Payload), `REVALIDATE_SECRET`, `NEXT_PUBLIC_SITE_URL` (cache clear; `.env.example`: `http://localhost:3001`), `LEGACY_BASE_URL` (default `https://ihna.edu.au`), `APPRUNNER_API_URL` (default the public App Runner host in `lib/config.ts`), `IMPORT_DRY=1` (same as `--dry`). `cli.ts`, `refresh-live.ts` and `fill-course-facts.ts` set `DISABLE_DB_PUSH=1` so only the dev server pushes schema (DEC-46).
- Live site (`LEGACY_BASE_URL`): GET only, no credentials, never a form post, at most one request per second (`course-live`, `staff`, `live-files`, staff photos), `media` with `p-limit` 4; `import:refresh` at most 2.5 requests per second.
- App Runner API: GET only, a request starts at most once per second (`lib/apprunner.ts` `pace`, up to 4 in flight); images from the S3 bucket `ihna-website.s3.ap-southeast-2.amazonaws.com` and inline images on `ihna.edu.au` / `www.ihna.edu.au`.

## 7. Import / seed

### 7.1 CLI
`npm run import -- <step|a,b,...|all> [--dry|--dry-run] [--force] [--only=<id|path>,...] [--<flag>=<value>]` (`tsx scripts/import/cli.ts`, Payload Local API).
- Steps are discovered from `scripts/import/steps/*.ts`; each exports `name`, optional `order` (default 100) and `run(ctx)` (contract in `lib/context.ts`). `all` runs the site's list `ALL_STEPS` (`lib/config.ts`); a comma list runs in the order given. No argument prints the step list.
- IHNA's `all` is `course-live,media,theme-photos,lookups,apprunner,wp-courses,staff,assign-images,link-course-managers,static,live-files,documents,link-course-brochures`. It leaves out `wp-posts`: IHNA's `posts.json` holds only the 4 WordPress posts at the site root, which are route files (DEC-42). `WP_POSTS_IMPORTED` (`lib/config.ts`) is false, so `npm run import -- wp-posts` refuses (`failed[{id: 'step'}]`, exit 1) and writes nothing.
- Report contract (`StepReport`): `site, step, dryRun, startedAt, finishedAt, created, updated, skipped, failed[{id, reason}], reviewQueue[{id, path, reasons, confidence}]` plus step-specific counters. A thrown step records `failed[{id: 'step'}]` and exits 1.
- `--only` limits a step to the listed ids/paths/slugs (`ctx.wanted`). `--force` overrides the edit-conflict guard (and, per step, overwrites files/images).
- Standalone runs: `npx tsx scripts/import/steps/<step>.ts [--dry] [--force] [--only=...]` for `lookups` and `wp-courses` (`runStandalone`, `lib/standalone.ts`); `npx tsx scripts/import/steps/static.ts [--dry]`.

### 7.3 Extractor (`html-to-blocks.ts`)
`extract(html, { url, wpType, allowedEmbedHosts? })` → `{ layout, confidence, coverage, unplaced, stats, warnings, unknownClasses, interactiveFallbacks, dropped }`; `lib/to-payload.ts` turns the intermediate layout into real blocks (`toPayloadBlocks`, `blocksToHtml`, `reviewReasons`) and `lib/lexical.ts` into Lexical via `convertHTMLToLexical` (jsdom). Used by `apprunner`, `wp-courses`, `wp-posts`.
1. A WordPress form's hidden `action` input becomes part of the form's action URL (`admin-post.php?action=…`), so the handler survives the first pass. `sanitize-html` then drops `script`, `style`, `noscript`, `on*`, `javascript:` and every iframe not on YouTube, Vimeo, Google Maps or the embed allowlist (`SEED_EMBED_HOSTS` in `lib/config.ts`: `my.matterport.com`, `forms.monday.com`, `ihna.online`, `healthcareers.elmotalent.com.au`, plus `ctx.allowedEmbedHosts`). `class`/`id`/`style` survive for recognition only.
2. Course-data shortcode output (`ul.start-date-ul`, a census table, `.cmCard` manager cards, and their literal unexpanded text) becomes a `courseData` placeholder; the selectors are documented in the file header.
3. A recursive walk recognises `tabs` (`.nav-tabs`, `.nav-pills`, `[role=tablist]` + panes, recursive), `accordion` (`.accordion-item`, `.card`, `.panel`; a table inside stays a nested `table`, DEC-15d), `table`, `videoEmbed` (YouTube/Vimeo, `.youtube-player[data-id]`, title from `data-title` or a caption heading beside it), `mapEmbed`, `iframeEmbed`, `imageText`, `cardGrid` (≥ 3 cards; `.owl-carousel` cards → carousel variant), `testimonial` (blockquote with a name, carousel quotes; never richText, DEC-15c), `enquiryForm` (form action → formKey via `lib/formkeys.ts`; other forms dropped), `cta` (link with a `*btn*` class), `hero` (`h1` and its image); everything else is prose → `richText`. `lib/formkeys.ts` maps IHNA's `admin_post_nopriv_*` handlers to `src/content/forms.ts` keys (`brchHndbk_enquiry` → `course-brochure`, `lp_enquiry` → `lp-enquiry`, `lib_enquiry` → `library-enquiry`, `feed_enquiry` → `quick-feedback`, `expression_of_interest` → `jobs-eoi`, …); they win over the shared names.
4. Links to the page's own host (the host of `ctx.url`, with `www.` and `uat.`) become site-relative; other hosts stay absolute.
5. Output HTML comes from an own serialiser that emits only `p, h2–h4, ul, ol, li, a[href], strong, em, img[src,alt], br`. `mailto:` not on `ROLE_MAILBOXES` and mobile `tel:` links lose the link, keep the text, and are counted (rule 4). An image not in the media map is dropped and reported.
6. Course fee text goes to `courses.fees`, not to a block (DEC-107); `FEES_WRAPPER_SELECTORS` is empty (DEC-15e).

`confidence = placed/expected − 0.05 × interactive fallbacks − 0.10 × unplaced`, clamped 0–1. `reviewReasons` adds `low-confidence` (< `CONFIDENCE_THRESHOLD` 0.85, DEC-15b), `low-coverage` (< `COVERAGE_THRESHOLD` 0.98), `theme-asset-link`, `unplaced:*`. Posts with any reason (also `flattened:<block>`, `dead-link`, `uat-link`, `empty-content`, `image-not-imported`, `inactive-in-source`) get `check`, else `auto`.

**Idempotency for posts** (`lib/upsert.ts`, key `import.apprunnerId`): `sourceHash` = sha of extractor version + source + resolved media ids + non-content data; equal hash → `skipped`. `contentHash` = `fingerprint()` (`lib/hash.ts`) of the content; if the stored content differs from it (edited in the admin) → skipped as a conflict with reason `edited-in-admin`, unless `--force`. A source change on an `ok` doc sets `check` + `source-changed`. A new item whose path is held by a hand-made doc is skipped (`path-held-by-hand-made-doc`). `assertNoLegacyMarkup` (`lib/assert-clean.ts`) runs before every write.

### 7.4 Courses (`wp-courses` → `ihna/wp-courses.ts`, `course-ihna.ts`)
21 course pages (`courses.json`), each its own course. Bodies are 30-480 KB, much of it inline CSS, JS and SVG.
- `prepareIhnaCourse` (`course-ihna.ts`) removes comments, `<style>`, `<script>`, `<svg>`, `<link>` and recognises three layouts: `v2` (15: masthead facts and student-type card, `#vTabs` tabs; the `.d-md-none` phone accordion repeats the tab text and is dropped; template sections `#cta-sec`, `#relatedBlogs`, `#respected-institution`, `#enquiry-sec`, `#flexible-classes-widget` dropped; `#testimonials-video` kept as videos), `short` (4 first-aid units: intro split at `h2`, the `.course-overview` facts table, `#courseAccordion` cards), `legacy` (2: the social-work package and the English preparatory course, through the shared `section-mapper.ts` `prepareCourseHtml`/`mapCourse`). YouTube widgets and carousels become `.youtube-player` (videos), written testimonials get `.testimonial-name`, a `blockquote.alert` becomes a note paragraph. Text left outside every placed part is flagged `text-left-outside-sections`.
- Facts read: title and code, delivery, duration, AQF level, placement hours, campuses (`IHNA_CAMPUSES`: Melbourne CBD, Heidelberg, Sydney, Perth, Brisbane), CRICOS, brochure/handbook/apply links, the switch link to the other-audience page, the audience, banner notices, and the fee (`.fee-box-lt` price card, else the first "total tuition / total fee / standard tuition fee … $X" line).
- `mapIhnaCourse` runs `extract()` on each labelled section and places it by `IHNA_RULES`, then the shared label rules; a slot fed by several labels keeps each label as an `h3`. The "Course Start Date(s)" section is the portal's expanded output: it is removed and `showStartDates` is written `true` (16 courses), so the startDates block reads the dates live (DEC-7).
- Fields: school, level, interest, university from the seed; campuses, delivery modes (`Face to Face`, `Blended`, `Online`) and a duration lookup (`<n> Months|Weeks|Years|Hours`) from the facts; `studentType` = the page's audience (else `domestic` for short courses, `both` for the others: 14 domestic, 5 international, 2 both); `courseType` `award` for Certificate III and Diploma, else `non-award`; `fees.displayAmount`/`note` = the fee (17 courses, DEC-107); `brochureUrl`, `handbookUrl` (FlipHTML5 viewers), `applyLink`, `units` ("made up of N units"), `excerpt` (the masthead subtitle, else the first intro paragraph). Key facts (`facts`, DEC-67) are left to `scripts/dev/fill-course-facts.ts`.
- `khId` (DEC-8): from `out/ihna-course-live.json`, `khIdSource: scrape`; the 4 courses with an empty field get `khId: null` and `kh-unresolved` (`/courses/hlt37525-certificate-in-pathology-pathology-collection-int/`, `/courses/chc52021-diploma-of-community-services-case-management-international-students/`, `/courses/diploma-of-community-service-to-bachelor-of-social-work/`, `/courses/ihna-english-language-preperatory-course/`).
- `hubspotCourseId` = the course code, unless one is already stored (typed in the admin); an unchanged, skipped course still gets an empty `hubspotCourseId` filled (no content write). 19 of 21 have one (the two pages without a code have none).
- Review status: `kh-unresolved` if no `khId`, else `check` with any reason, else `auto` (17 `auto`, 4 `kh-unresolved`). Coverage ≥ 98% on all 21 (average 99.9%).

### 7.5 Refresh from live
- **App Runner** (posts, galleries, blog categories): `npm run import -- apprunner --refresh` re-fetches the API snapshots and re-imports what changed (DEC-53).
- **Courses**: the bodies come from `courses.json`, which `import:refresh` re-fetches; `khId` and the featured image come from `npm run import -- course-live --refresh`; then `wp-courses`.
- **Staff**: delete `scripts/import/out/cache/live-staff/`, then `npm run import -- staff`.
- **WordPress** (`npm run import:refresh`): `scripts/import/refresh-live.ts [-- --dry] [--resume] [--force] [--lazy] [--no-import] [--no-recover] [--no-content-diff]`; pure logic in `lib/refresh.ts`, file recovery in `lib/recover-missing.ts`.
  1. Re-fetches pages, posts, courses from the WP REST API (GET, ≤ 2.5 req/s) into `../inventory/data/ihna/`, keeping the old files as `*.prev.json`.
  2. Diffs by `id` + `modified` (and body unless `--no-content-diff`) → `../inventory/data/ihna/refresh-<date>.report.json`.
  3. Runs `media`, `wp-posts`, `wp-courses`, `staff` through `cli.ts` with `--only=<new/changed ids>`; step reports are archived in `out/refresh/<date>/`. Docs with `reviewStatus: ok` are skipped and listed. An item deleted on live is never deleted: its doc gets `check` + reason `deleted-on-live`. A new, changed or deleted WordPress page runs no step and is listed under `import.pagesChangedOnLive` / `import.pagesDeletedOnLive` (id, path, title, `routeFile`) for a developer to update the route file (DEC-61). Then clears the page cache at `NEXT_PUBLIC_SITE_URL`, else `DEV_SITE_URL` (`http://localhost:3001`).
  An unfinished import leaves `importPending: true`; the next run refuses to fetch until `--resume`.

### 7.7 Tracking sheet (`../inventory/v2/ihna/TRACKING.csv`, DEC-37)
The place to look for "is this URL done": one row per public URL of the old site (1002 rows: pages, landing pages, courses, posts, documents, redirects and `gone` rows), each with `url`, `type`, `where` (route file, `cms:<collection>`, `redirect -> …` or `none`), `status` (`done`, `check`, `todo`, `gone`), `note`, `checked`. ## 9. Differences from ihm-web
- `SITE = 'ihna'`, `LEGACY_ROOT = ../ihna-web-2.0`, `LEGACY_BASE_URL` default `https://ihna.edu.au` (`lib/config.ts`); `seeds/` is site-specific (ihm-web has its own `seeds/documents.ts` and `static-held.json`). The rest of `scripts/import/**` is shared (SHARED-FILES.md); IHNA's copy carries the site branches.
- IHNA-only steps and files: `course-live`, `apprunner`, `live-files`, `link-course-brochures`, `lib/apprunner.ts`, `course-ihna.ts`, `ihna/{wp-courses,staff,groups}.ts`, `seeds/ihna-course-groups.json`. ihm-web has none of them.
- `lookups`, `wp-courses` and `staff` branch on `SITE`: IHNA's lookups come from a seed (ihm-web derives provisional ones from course HTML); IHNA's `khId` is read from the live page (ihm-web uses the theme evidence in `kh-id.ts`); IHNA's staff come from `/staff-profile/?id=N` pages (ihm-web parses WordPress profile pages with `lib/staff-parse.ts`).
- IHNA's blog comes from App Runner (`apprunner`, keyed by `apprunnerId`); ihm-web imports WordPress posts with `wp-posts`, which IHNA does not run.
- `theme-photos` takes only photographs a page or course body shows; ihm-web takes every theme photograph that passes the rules.
- IHNA courses set `showStartDates` where the page showed portal dates (16); ihm-web writes `false`. IHNA hoists nothing to `courseShared`.
- The two `legacy` IHNA course bodies use ihm-web's mapper (`section-mapper.ts`); `tests/courses/section-mapper.test.ts` tests that mapper on `../inventory/data/ihm/courses.json`.
- `documents` refreshes metadata of existing rows and keeps the static copies in `public/`; ihm-web keeps existing rows as marketing left them and deletes the static copy after import.
